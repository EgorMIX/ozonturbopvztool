# Ozon Turbo-PVZ Timer — расширение Chrome (MV3)

Расширение для работы на `turbo-pvz.ozon.ru`. Следит за таймером приёмки и оповещает (голос, push, Telegram,
ntfy) на порогах 30/15/5 минут. Второй модуль — «Авто-пакеты»: на экране выдачи сам нажимает «+» у пакетов M/L
(фильтр размера, лимиты, статистика). Подпись в футере popup: «Создано с помощью Claude AI · Идея: EgorMIX» — оставлять.

Общайся с владельцем по-русски; комментарии в коде и тексты интерфейса тоже русские.

## Команды (Node >= 18, зависимостей нет, `npm install` не нужен)
- `npm run check` (= `node scripts/check.mjs`) — статическая проверка: синтаксис, дубли функций / веток сообщений /
  `id` / обработчиков / больших блоков, `getElementById` из `popup.js` существует в `popup.html`, отправленные
  сообщения обрабатываются, права в манифесте, случайно попавшие токены. **Запускай после каждой правки.**
  Код возврата 1 = есть НОВАЯ ошибка. Известные ошибки лежат в `scripts/known-issues.json` (не валят проверку; при
  исправлении удали ключ). `npm run check:strict` считает и их.
- `npm run pack` — проверка + `dist/ozon-turbo-pvz-<версия>.zip` (без внешней утилиты zip; `dist/` в `.gitignore`).

## Запуск в Chrome (делает владелец; в среде Claude Code браузера, скорее всего, нет)
1. `chrome://extensions` → «Режим разработчика» → «Загрузить распакованное» → папка **`extension/`** (не корень репозитория).
2. После правок: кнопка ⟳ у расширения **и обновить вкладку Ozon** (иначе в ней остаётся старый content-скрипт →
   «Extension context invalidated»).
3. Логи: service worker — ссылка «Service worker» на карточке расширения; popup — ПКМ по иконке → «Проверить
   всплывающее окно»; content-скрипты — консоль вкладки Ozon (`[PVZ…]`).

Проверить правку в браузере ты не можешь — в ответе пиши владельцу, **что именно открыть и нажать** и что должно произойти.

## Структура
```
extension/            ← код расширения; только это грузится в Chrome и пакуется в zip
  manifest.json       MV3, версия 1.4.0
  background.js       service worker: состояние, алармы, push/голос/Telegram/ntfy, прокси, режимы
  content.js          поиск таймера на /receiving…, шлёт секунды в SW
  speech.js           озвучка (SpeechSynthesis) по сообщению SPEAK
  bags-content.js     «Авто-пакеты» на /orders/session-new/<id>
  popup.html / .js    интерфейс: вкладки «Таймер» и «Пакеты», настройки, тесты, отладка, журнал
scripts/              check.mjs, pack.mjs, known-issues.json
docs/                 architecture.md, known-issues.md, backend-idea.md, fixtures/ (HTML-образцы страниц Ozon)
```
Подробности — не дублирую, читай по необходимости:
- `docs/architecture.md` — потоки данных, таблица сообщений, схема `chrome.storage`, алармы, DOM Ozon, подводные камни.
- `docs/known-issues.md` — что сломано или рискованно, по приоритетам, с планом исправления.
- `docs/backend-idea.md` — открытое решение: серверный таймер или чинить прокси.
- `docs/fixtures/` — HTML-образцы страниц Ozon (таймер, блок пакетов) для правки селекторов.

## Правила работы с кодом
1. **Правь точечно инструментом Edit.** Не дописывай блоки «в конец», не патчь файлы скриптами/регулярками вслепую:
   так раньше размножились куски кода (4 копии секции ntfy в `popup.html`, дубли `sendNtfy` и обработчиков).
   Перед добавлением функции или секции сделай grep — нет ли такой уже. После правки — `npm run check`.
2. **Классы Ozon хэшированы** (`_timer_hamc7_24`, `ozi__input__root__L1Lw-`) и меняются при релизах. Селекторы —
   по стабильным фрагментам (`_timer_`, `paragraph-large`, `increment`, `inputmode="decimal"`) и по тексту; сверяйся с
   `docs/fixtures/`. В блоке пакетов контейнер — `el.parentElement`, а не `closest()` (иначе захватит чужой блок).
3. **Service worker эфемерный.** Не полагайся на переменные между событиями: состояние — в `chrome.storage`, и перед
   обработкой события его надо дождаться: в `background.js` каждый обработчик начинается с `await ready`
   (промис загрузки из storage) — новые обработчики событий SW пиши так же.
4. **HTTP-заголовки только ISO-8859-1.** Кириллицу и эмодзи в заголовки не класть. ntfy отправляется JSON-API
   (`POST <server>` с телом `{topic, message, title, …}`) — не возвращай заголовки `Title`/`Tags`.
5. **Новое сообщение** между частями расширения = ветка в `onMessage` в `background.js` + отправитель; типы пиши
   ЗАГЛАВНЫМИ_С_ПОДЧЁРКИВАНИЕМ. Новая настройка = дефолт в `background.js` (`DEFAULT_SETTINGS`) **и** в `popup.js` (`settings`).
6. **Content-скрипты** перед любым `chrome.*` проверяют `chrome.runtime?.id` (расширение могло перезагрузиться).
7. **Секреты** (токен Telegram-бота, токен/топик ntfy, логин/пароль прокси) живут только в `chrome.storage.local` и в
   интерфейсе. Не клади их в репозиторий, фикстуры, логи, сообщения коммитов. Перед сохранением логов консоли или HTML с
   Ozon вырежи всё личное: в логах встречается `access_token` сессии Ozon (JWT в адресе WebSocket), имена, телефоны.
   `npm run check` ловит типичные токены, но это страховка, а не замена внимательности.
8. **Разрешения и `host_permissions`** в манифесте — только то, что реально нужно; расширение набора может потребовать от
   владельца повторного подтверждения в Chrome — упомяни это в ответе.
9. **Не коммить и не пушь, пока владелец не попросил.** Версию в `manifest.json` не меняй сама; при ближайшем релизе её
   нужно поднять до 1.5.0 (модуль пакетов добавлен после 1.4.0).
10. Новых зависимостей и сборщиков не добавляй без просьбы: расширение — простые файлы, загружаемые «как есть».

## Что сломано или рискованно (кратко; подробно, с планом исправления — `docs/known-issues.md`)
**P0 (надёжность уведомлений):**
1. ~~SW не дожидается загрузки состояния из storage~~ — исправлено (`await ready`), ждёт проверки в Chrome.
2. Модуль прокси: на каждом старте SW ставит `direct` и перетирает прокси пользователя; включённый прокси действует на
   весь HTTPS браузера; логин/пароль не применяются. Пока не починен — не включать.
3. Любое «Сохранить» в popup (в том числе на вкладке «Пакеты») сбрасывает `firedFor` → пройденные пороги шлются повторно.
4. Нет понятия «сессия приёмки» (предложение: `endsAt` = время окончания): следующая приёмка после `TIMER_LOST` не
   получает «Приёмка начата».

**P1 («Авто-пакеты»):** 5. квота не ограничивает серию кликов (перебор), счётчик в памяти вкладки расходится со storage
после сброса, возможен повторный запуск серии; 6. дубль обработчика `#bagsEnabled` + обращение к удалённому `#bagsStatus`
(это ловит `npm run check`, ключи в `scripts/known-issues.json`).

**Открытое решение:** серверный таймер (Telegram/ntfy независимо от браузера) или починка прокси — `docs/backend-idea.md`.
Рекомендуемый порядок: п. 1 → 4 → 3 → 2 → 5–6 → мелочи (P2) → сервер.
