# Известные проблемы и ограничения — 1.8.0

## Исправления аудита 1.7.0

- История обновляется во время приёмки и при изменении storage; финальный статус не отбрасывает последнее число
  отправлений. Проверены две перевозки: 178 принято из 541, затем 541 из 541.
- Старый активный таймер получает запись истории; очистка сохраняет текущую приёмку.
- Изменение запаса времени согласованно меняет крайний срок и результат текущей приёмки.
- Привязка таймера к вкладке защищает от чужого `TIMER_LOST` и подмены другой открытой вкладкой.
- Корректировка `endsAt` переносит расписание. При запуске SW восстанавливаются алармы, пауза и ожидание
  пропавшего таймера. Запас 0 минут не теряет оповещение о крайнем сроке.
- Скрытые таймеры исключены; SPA-навигация отменяет отложенный запуск предыдущего сканирования.
- Квоты и статистика пакетов сериализованы в SW: резерв до клика, подтверждение изменения поля после него.
  Глобальное отключение блокирует пакеты. Сброс счётчика выполняется через SW.
- Повреждённый импорт отклоняется до записи. Частичное сохранение не сохраняет чужие черновики.
- Исправлен показ порогов. Свой ntfy получает доступ через optional permissions.
- `onMessage` возвращает `true` для асинхронной очереди состояния; неизвестные команды получают явный ответ.
  Это не ошибка незакрытого канала. `badge_tick` использует поддерживаемый Chrome 108 период 1 минута.

## Проверки

`npm run check:strict`, `npm test`, сборка ZIP. HTML и popup проверены в Chromium с подменённым Chrome API,
связанным с настоящим кодом SW. Скрипт браузерной проверки находится вне репозитория.
Полная загрузка расширения запрещена политикой тестовой среды; живой Ozon и внешняя доставка не проверены.

## Оставшиеся ограничения платформы и модели

- Завершение определяется по исчезновению таймера с ожиданием 2 минуты от ререндеров. Это наблюдение DOM,
  а не подтверждение API Ozon. Сам переход на другой экран не доказывает завершение; при закрытой или замороженной
  вкладке результат может быть «нет данных».
- Поддерживается один активный таймер; независимый учёт нескольких ПВЗ — отдельная функция.
- При закрытом Chrome, сне компьютера и недоступности сети доставка не гарантируется. Серверный таймер — отдельная
  предлагаемая функция (`backend-idea.md`). Chrome может задерживать алармы при нагрузке и сне.
- Изменение DOM Ozon требует обновления селекторов. Пропущенные в старых версиях данные нельзя восстановить,
  если расширение их никогда не видело.
- Счётчик пакетов подтверждает изменение поля, а не физическую выдачу или завершение заказа. DOM и storage
  не составляют одну транзакцию: резерв незавершённого клика истекает через 2 минуты. Квоты накопительные
  до ручного сброса; лимит «на заказ» не вводился.
- Секреты находятся локально в профиле Chrome. Запросы Telegram/ntfy имеют таймаут 15 секунд; автоматического
  повторения отправки нет, при недоступности сервиса уведомление может не дойти.
- Прокси Chrome один: PAC направляет через прокси Telegram, остальные сайты — DIRECT. Системный прокси
  не наследуется, пока этот режим включён. SOCKS5 с логином и MTProto не поддерживаются.

## Проверка владельцем после обновления

1. Перезагрузить расширение и вкладку Ozon; в popup должна быть версия 1.8.0.
2. Открыть «История» во время приёмки: перевозки и число отправлений должны совпадать с Ozon.
3. Завершить приёмку и подождать 2 минуты: запись закрывается, финальные числа остаются;
   время доставки из виджета не становится новым таймером.
4. Проверить голос, push и используемые каналы кнопками тестирования. Не публиковать секреты и клиентские данные.
